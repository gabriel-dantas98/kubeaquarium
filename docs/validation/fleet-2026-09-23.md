# Fleet, spacious aquarium and launch media validation

## Delivered behavior

- Nautilus, Manta and Atlas have distinct procedural silhouettes, readable local
  lighting, persisted selection and shared navigation controls. Hull replacement
  disposes geometry/materials and preserves the camera pose.
- CPU and memory allocations use separate reference units for whale scale.
  Bubble volume follows whale volume; seeded spacing, rotated spawn cells and
  jitter leave wider navigation channels. Growth preserves namespace bearings;
  unchanged and shrinking layouts retain positions. These are configured resource
  allocations, not measurements of live utilization.
- README launch media now has bundled licensed typography, illustrated whale and
  chart graphics, vessel selection footage, and observed recovery captions.
- The media review skill is linked from AGENTS.md and the release skill. See
  [demo maintenance](../demo-maintenance.md) for both builds and Pages publication.

## Verification

Passed TypeScript, production frontend and static-demo builds, Go tests and vet,
video lint, navigation, scene, radar, labels, recovery unit/browser checks and the
repeatable demo mission. Namespace tests cover sparse through 2,000-pod placement,
minimum spawn spacing, deterministic layout, growth channels and resource scaling.
Vehicle tests cover distinct shapes, retained pose and resource disposal.

The built static demo loaded at `/kubeaquarium/` without `?demo`, with 203 synthetic
pods. All three selections persisted across reloads. No API HTTP requests,
WebSockets or browser errors were observed. The PR CI now also type-checks the
frontend, builds the static demo and runs Go tests.

The [short performance run](fleet-2026-09-23/smoke-metrics.json) exercised 20, 200
and 2,500 pods across overview, filtering, radar, dive and impact. All 15 windows
completed; each impact issued one mocked delete. p95 frame intervals ranged from
17.1 to 17.6 ms; one frame interval exceeded 50 ms. This was a three-second sample
per scenario with one-second warmup, on a machine also doing validation work. It
is a smoke check, not a repeat of the historical comparative performance gate.

## Media verdict: refreshed

All 16 desktop/narrow screenshots were regenerated; automated label/panel overlap
checks passed. Inspected overview and dive screenshots and representative launch,
fleet and observed-Ready frames. Visual QA caught regular-looking spawn rows;
seeded 3D rotation and stronger decorrelated jitter were applied before final capture.

The gameplay capture checked request, absence, matching-controller replacement and
Ready states under network guards. MP4: 1440×940, 30 fps, 1,138 frames, approximately
38 seconds. GIF and observed-Ready poster were regenerated from the same capture.
The separate [playthrough](fleet-2026-09-23/playthrough.webm) uses real keyboard
movement and right-drag steering for each vessel; its [report](fleet-2026-09-23/playthrough.json)
records the assertions. Visual review used sampled frames rather than continuous
manual playback. No real Kubernetes mutation was used for these checks.
