# Release

Use this when the user asks to "cut a release", "bump the version", or "publish a new
version" of kubeaquarium.

## How releases work here

Pushing a tag matching `v*` to `origin` triggers `.github/workflows/release.yml`, which
builds the frontend, runs `goreleaser release --clean`, and publishes a public GitHub
Release with binaries for darwin/linux/windows (amd64/arm64) plus `checksums.txt`. There
is no manual upload step — the tag push *is* the release. Treat pushing a `v*` tag as a
release action requiring explicit user confirmation before you do it.

## Steps

1. **Check for pending work.** `git status`, `git log origin/main..HEAD` — make sure
   everything intended for the release is merged into `main`. If there's an open PR with
   the changes, confirm with the user whether to merge it first (squash merge is the
   convention here — see recent `git log` for examples).
2. **Sync main.** `git checkout main && git pull origin main`.
3. **Pick the next version.** `git tag --sort=-v:refname | head -5` for the latest tag.
   Follow semver: patch for bug/behavior fixes, minor for new features, major for
   breaking changes. Confirm the version with the user before tagging — it's
   public and hard to walk back cleanly (deleting/retagging a released tag is messy).
4. **Tag and push.**
   ```bash
   git tag -a vX.Y.Z -m "vX.Y.Z"
   git push origin vX.Y.Z
   ```
5. **Watch the workflow.**
   ```bash
   gh run list --workflow=release.yml --limit 1
   gh run watch <run-id> --exit-status
   ```
6. **Verify the release.**
   ```bash
   gh release view vX.Y.Z --json url,isDraft,isPrerelease,assets \
     --jq '{url,isDraft,isPrerelease,assets:[.assets[].name]}'
   ```
   Expect 5 archives (`darwin_amd64`, `darwin_arm64`, `linux_amd64`, `linux_arm64`,
   `windows_amd64`) plus `checksums.txt`, `isDraft: false`.
7. Report the release URL back to the user.

## Notes

- `internal/webassets/dist/` (the built frontend) is committed to the repo and embedded
  into the Go binary — if frontend source changed, make sure `web-build` output was
  committed in the merged PR, not just built locally.
- The release changelog is auto-generated by goreleaser from commit messages between
  tags, excluding `docs:`, `chore:`, `ci:`, and merge commits (see `.goreleaser.yaml`
  `changelog.filters`).
- Homebrew tap publishing is commented out in `.goreleaser.yaml` pending a
  `homebrew-tap` repo + `HOMEBREW_TAP_TOKEN` secret — leave it as-is unless the user asks
  to enable it.
